- UI 不直接调用 Windows API，通过 UiState 中的 request 标志交给 App 执行。

- 进程、管道、文件落盘只允许出现在 services 与 platform；UI 线程只做事件取出与绘制。

### 2.3 关键设计决策

1. 分层：core -> model -> App -> main；ui 只依赖 model/core，platform 只被 App 调用。
2. 面板无状态：每个面板是 `DrawXxx(AppModel&)` 函数，状态全部在 AppModel。
3. 平台解耦：面板只发出 request 标志，原生文件对话框由 App 统一打开。
4. 服务隔离：TaskController 只消费 ITaskRunner 事件，TaskService 负责探测/编码/落盘，替换实现不影响 UI。
5. DPI：布局常量统一通过 `ui::S()` 缩放，与字体、样式缩放保持一致。
6. 字体：优先 `assets/fonts/SourceHanSansCN-Regular.ttf`，缺失时回退 Windows 中文字体。
7. 交互保护：处理中禁止增删队列，当前任务使用启动时的快照。
8. 命令安全：全程参数数组；引号/反斜杠只在 services/CommandLine 一处处理。
9. 落盘安全：先写同目录临时文件，成功后 MoveFileEx 原子重命名，绝不覆盖源文件。
10. 诊断隔离：技术细节只进日志；界面只展示 ErrorFormatter 生成的中文文案。
11. 意图与执行分离：界面只出现 H.264 / H.265 / 只要声音；`model::ConvertMapping` 负责映射到
    `TargetFormat + VideoCodec + slim + quality + suffix`，可单测。
12. 兼容优先：H.265 + MP4 强制 `-tag:v hvc1`；x265 关闭 info 横幅；奇数分辨率补偶数缩放。
13. 自动命名：默认 `_H264` / `_H265` / `_音频`，避免同一文件不同结果互相覆盖；可在设置改回手动后缀。

## 3. 已知限制与风险

1. 只有“编码转换”场景会执行真实任务；剪辑/滤镜/录屏/批量面板点开始会提示开发中。
2. 输出编码只支持 H.264 / H.265：AV1 可作为输入，暂不作为输出；GIF 未实现。
3. 设置不持久化：输出目录、后缀、深色主题、完成后打开文件夹在重启后恢复默认。
4. 处理中禁止增删队列（任务启动快照）；尚未实现“下一批”策略。
5. 探测在 worker 内同步执行，最长 20 秒；取消需要等当前探测返回（本地文件通常 <100ms）。
6. 硬件加速为“先尝试 NVENC，失败再回退”，没有启动预检测；无 NVIDIA 时每个文件多一次失败尝试（耗时很短）。
   缺少 libx265 的处理组件会让 H.265 失败，界面会提示改用 H.264。
   10-bit / HDR 源统一转为 yuv420p，可能损失色深。
7. 错误分类覆盖常见 stderr（缺失/损坏/权限/磁盘/编码器/长路径）；未知错误仍是通用“处理失败，请重试”。
8. 内置 ffmpeg 目录已预留但未提交二进制：需要用户安装 FFmpeg，或手动放入 `assets/ffmpeg`（含 `ffmpeg.exe` / `ffprobe.exe`）。
9. FFmpeg 分发许可证、裁剪范围、包体积尚未确定。
10. 字体未随包分发，依赖系统字体；正式交付需解决思源黑体授权与体积。
11. 体积估算仍是经验公式，不是编码结果。
12. 水印预览是绘制示意图，不是真实视频帧；录屏/截图仍为 UI 演示。
13. 无崩溃恢复与日志导出界面；日志只写到程序目录 `logs/easyav.log`。
14. Win32 与 x64 共用 Debug/Release 输出目录，两个平台不能同时保留产物。
15. 当前仅实现 Windows 版本：FfmpegProcess/Job Object/AppPaths 使用 Win32 API；
    Linux/macOS 的 Makefile 目标编译不过，需要补非 Windows 服务实现。
16. 尚未测量 60 FPS、空闲 CPU、内存 <100MB 等 SRS 性能指标。

### 4.2 目标架构

> 以下为当时的计划草案；实际模块名与职责见 4.5。

新增 `src/services/`，作为业务能力的唯一实现层：

```
src/services/
  IMediaProbe.h            探测接口：读取时长/编码/分辨率
  ITaskService.h           任务服务接口：提交、取消、轮询事件
  FfmpegLocator.h/.cpp     查找内置 ffmpeg/ffprobe，校验版本
  FfmpegCommandBuilder.h/.cpp  纯函数：参数数组 + 输出路径，可单测
  FfmpegProcess.h/.cpp     CreateProcessW + 匿名管道 + Job Object
  ProgressParser.h/.cpp    解析 -progress pipe:1 的 out_time_us 等键值
  MediaProbe.cpp           基于 ffprobe 或 libavformat 的探测实现
  TaskService.cpp          后台线程 + 线程安全事件队列
```

数据流：

```
UI 点击开始
  -> AppModel 生成 TaskRequest（文件快照 + 参数快照 + 输出设置）
  -> ITaskService::Submit
  -> 后台线程：探测 -> 生成参数 -> 启动进程 -> 读 stdout/stderr
  -> 事件队列（进度/日志/完成/失败）
  -> TaskController 在 UI 帧内 Drain
  -> 面板显示进度、文件、中文错误
```

关键约束：

- UI 线程禁止调用 CreateProcess、WaitForSingleObject、文件探测等阻塞操作。
- 命令只通过参数数组构造，禁止拼接裸 shell 字符串；路径转义必须覆盖空格、中文、引号、反斜杠结尾。
- 使用 `CREATE_NO_WINDOW`；标准输出/错误通过匿名管道读取。
- 取消时先尝试优雅终止，再 Job Object 兜底；必须清理临时文件。
- 输出先写临时文件，成功后原子重命名，避免半成品。

### 4.5 实际实现与差异

实际新增模块（均位于 `src/services/`，契约在 `src/core/`）：

| 模块 | 作用 |
| --- | --- |
| `core/TaskContracts.h` | TaskRequest / TaskEvent / FileFailure / MediaInfo / ToolStatus 等纯数据契约 |
| `core/ITaskRunner.h` | 任务端口；TaskController 只依赖它 |
| `FfmpegLocator` | 环境变量 → PATH → 内置 assets → exe 同目录 → cwd，`-version` 校验 |
| `CommandLine` | 参数数组 → Windows 命令行，唯一负责引号/反斜杠转义 |
| `FfmpegProcess` | CreateProcessW + 隐藏窗口 + 双管道 + Job Object + 取消/超时 |
| `IMediaProbe` / `FfprobeProbe` / `ProbeOutputParser` | ffprobe 文本探测（非 JSON），失败不影响入队 |
| `ProgressParser` | `-progress pipe:1` 流式解析，支持任意分片 |
| `FfmpegCommandBuilder` | 参数数组 + 质量映射（MP4/MKV/MP3、GPU 分支） |
| `OutputNamer` | 后缀清洗、同名编号、临时文件路径、长路径保护 |
| `ErrorFormatter` | stderr/退出码 → FailureKind → 中文文案 |
| `Logger` | 线程安全文件日志，2MB 轮转 |
| `TaskService` | 单 worker、去重探测、逐文件执行、事件队列、取消清理 |

与计划的差异：

1. 没有独立的 `ITaskService`/`MediaProbe.cpp`：探测端口为 `IMediaProbe`，任务服务直接实现 `ITaskRunner`。
2. ffprobe 使用 `-of default=noprint_wrappers=0` 文本输出，自写状态机解析，避免引入 JSON 库。
3. 取消采用立即 `TerminateProcess` + Job Object，删除临时文件，不保留半成品（原开放决策 8 的答案）。
4. FFmpeg 查找顺序按用户约定：优先系统 PATH，其次内置目录；`%EASYAV_FFMPEG_DIR%` 可覆盖。
5. 质量→CRF/preset/码率映射已实现，提前完成 V0.5 的一部分。
6. 输出采用“同目录临时文件 + MoveFileEx 原子重命名”，并处理编码期间出现的同名竞争。
7. 测试使用自带断言 + `tests/run_tests.bat`，未引入第三方框架，也未把测试工程加入 `EasyAV.slnx`。

## 10. 决策记录

已决定：

1. **FFmpeg 分发**：使用独立 exe；查找顺序 `%EASYAV_FFMPEG_DIR%` → 系统 PATH →
   内置 `assets/ffmpeg` → exe 同目录 → cwd。内置二进制、裁剪范围与许可证仍待打包阶段处理。
2. **媒体探测**：ffprobe 子进程 + 文本解析，不引入 JSON 库、不在进程内链接 libavformat。
3. **显卡策略**：不预检测，先尝试 NVENC（H.264/H.265），非输入类错误时回退软件编码一次。
4. **取消语义**：立即 `TerminateProcess` + Job Object 兜底 + 删除临时文件，不保留半成品。
5. **输出策略**：后缀 + 同名编号；临时文件与最终文件同目录，`MoveFileEx` 原子重命名，绝不覆盖源文件。
6. **测试方式**：自带断言 + `tests/run_tests.bat`，不引入第三方框架，不加入 slnx。
7. **编码目标**（V0.2）：只支持 H.264 / H.265；AV1 可作为输入，暂不作为输出；不以 `-c:v copy`
   代替编码转换（需要判断音轨/容器兼容性，风险高）。
8. **HEVC 兼容**：H.265 + MP4 强制 `-tag:v hvc1`；x265 关闭 info 日志；奇数尺寸补偶数缩放。
9. **命名**：默认按结果自动命名 `_H264` / `_H265` / `_音频`，避免同一文件不同目标互相覆盖；
   设置里可关闭并手填后缀。

仍待决定：

1. 内置 FFmpeg 的版本、裁剪模块、许可证与包体积。
2. 配置文件放程序目录（绿色便携）还是 %APPDATA%。
3. 是否需要真实视频预览；解码与渲染成本需单独立项。
4. 批量处理是否需要“单文件覆盖规则”，会影响 TaskSettings 数据模型。
5. 思源黑体是否随包分发（授权与体积）。
6. 处理中继续添加文件时，新文件归属当前批还是下一批。
7. QSV/AMF 的实机支持范围与回退顺序。
8. AV1 输出的编码器选择（SVT-AV1 / libaom）与速度提示。
9. `-c:v copy` 无损重封装快路径的启用条件与失败回退。
