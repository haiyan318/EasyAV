## 2. 已完成内容

### 2.1 代码结构与依赖方向

| 目录/文件 | 职责 | 依赖 |
| --- | --- | --- |
| main.cpp | 窗口、OpenGL/ImGui 后端、拖拽事件转发 | App、Theme |
| src/App.h/.cpp | 应用外壳：装配模型、面板、平台能力 | model、ui、platform |
| src/core | 纯数据与工具：Types、Format、Text | 仅标准库 |
| src/model | 队列、场景参数、任务状态、聚合根 AppModel | core |
| src/platform | 文件/文件夹选择、打开资源管理器 | core/Text |
| src/ui | 主题、字体、通用控件、Labels | core、ImGui |
| src/ui/panels | 顶栏、队列、场景标签、5 个场景面板、操作栏、状态栏、设置、Toast | model、ui |

约束：

- core 与 model 不引用 ImGui，便于单元测试和后续替换。
- 面板之间不互相 include，只读写 AppModel，避免界面模块耦合。
- UI 不直接调用 Windows API，通过 UiState 中的 request 标志交给 App 执行。
- 任务执行的唯一接入点是 TaskController，后续可替换其内部实现而不改面板。

### 2.3 关键设计决策

1. 分层：core -> model -> App -> main；ui 只依赖 model/core，platform 只被 App 调用。
2. 面板无状态：每个面板是 `DrawXxx(AppModel&)` 函数，状态全部在 AppModel。
3. 平台解耦：面板只发出 request 标志，原生文件对话框由 App 统一打开。
4. 演示隔离：TaskController 是唯一“假进度”实现，注释明确标注，替换时不影响 UI。
5. DPI：布局常量统一通过 `ui::S()` 缩放，与字体、样式缩放保持一致。
6. 字体：优先 `assets/fonts/SourceHanSansCN-Regular.ttf`，缺失时回退 Windows 中文字体。
7. 交互保护：处理中禁止增删队列，防止用户误以为新文件会加入当前任务。

## 3. 已知限制与风险

1. 无 FFmpeg：所有“处理”只推进 UI 进度，不产生输出文件。
2. 时长未知：MediaItem::durationSec 固定为 0，剪辑时间轴按百分比显示。
3. 体积估算为经验公式，不是编码结果；接入后应替换为基于码率/时长的估算或直接显示实际结果。
4. 水印预览是绘制出的示意图，不是视频帧；接入解码后才能实现所见即所得。
5. 录屏/截图仅改变 UI 状态，没有屏幕采集、摄像头采集或文件写入。
6. 批量处理目前是“全局规则”，没有单文件覆盖规则；后续如需单独设置要扩展数据模型。
7. 处理中锁定队列是演示期的保护措施；接入真实任务后应改为“任务快照 + 队列可继续添加”，并明确新文件属于下一批。
8. 字体未随包分发，依赖用户系统字体；正式交付需解决思源黑体授权与体积问题。
9. 未做设置持久化，重启后输出目录、主题、后缀恢复默认。
10. 未做日志与崩溃恢复；FFmpeg 子进程异常退出时目前没有可诊断信息。
11. 没有自动化测试；路径转义、进度解析等高风险代码接入后必须补测试。
12. 尚未测量 60 FPS、空闲 CPU、内存 <100MB 等 SRS 性能指标。

## 4. 下一阶段：V0.1 MVP（真实处理链路）

### 4.1 阶段目标

完成“拖入文件 -> 选择结果 -> 开始 -> 真实调用 FFmpeg -> 进度/取消 -> 输出文件”的最小闭环。

范围建议（对应 SRS V0.1）：

- FFmpeg 子进程封装（隐藏控制台窗口）。
- MP4 -> MP3 音频提取。
- MP4 -> MP4 压缩/转码（质量滑块映射 CRF/preset）。
- 队列时长探测。
- 进度解析与取消。
- 输出命名防覆盖、失败中文提示。

### 4.2 目标架构

新增 `src/services/`，作为业务能力的唯一实现层：

```
src/services/
  IMediaProbe.h            探测接口：读取时长/编码/分辨率
  ITaskService.h           任务服务接口：提交、取消、轮询事件
  FfmpegLocator.h/.cpp     查找内置 ffmpeg/ffprobe，校验版本
  FfmpegCommandBuilder.h/.cpp  纯函数：参数数组 + 输出路径，可单测
  FfmpegProcess.h/.cpp     CreateProcessW + 匿名管道 + Job Object
  ProgressParser.h/.cpp    解析 -progress pipe:1 的 out_time_us 等键值
  MediaProbe.cpp           基于 ffprobe 或 libavformat 的探测实现
  TaskService.cpp          后台线程 + 线程安全事件队列
```

数据流：

```
UI 点击开始
  -> AppModel 生成 TaskRequest（文件快照 + 参数快照 + 输出设置）
  -> ITaskService::Submit
  -> 后台线程：探测 -> 生成参数 -> 启动进程 -> 读 stdout/stderr
  -> 事件队列（进度/日志/完成/失败）
  -> TaskController 在 UI 帧内 Drain
  -> 面板显示进度、文件、中文错误
```

关键约束：

- UI 线程禁止调用 CreateProcess、WaitForSingleObject、文件探测等阻塞操作。
- 命令只通过参数数组构造，禁止拼接裸 shell 字符串；路径转义必须覆盖空格、中文、引号、反斜杠结尾。
- 使用 `CREATE_NO_WINDOW`；标准输出/错误通过匿名管道读取。
- 取消时先尝试优雅终止，再 Job Object 兜底；必须清理临时文件。
- 输出先写临时文件，成功后原子重命名，避免半成品。

## 8. 开发约定

1. 界面不出现命令行参数、编码器名、CRF 等专业术语。
2. 任何阻塞操作不得放在 UI 线程。
3. 命令必须在 services 层构造，禁止在面板中拼接；路径必须转义。
4. 默认不覆盖源文件，输出失败不得留下半成品。
5. 新增面板遵循：只读写 AppModel、不 include 其他面板、颜色取 Theme、尺寸用 ui::S()。
6. 新增源文件需同步更新 EasyAV.vcxproj、.filters、Makefile、build_win32.bat。
7. 新增用户文案保持口语化中文，并同步错误汉化表。
8. 文档与实现同步：完成一项待办即更新本文档和 README。

2. 媒体探测使用 ffprobe 子进程还是 libavformat 进程内调用？
3. 配置文件放程序目录（绿色便携）还是 %APPDATA%？
4. 显卡编码检测策略：启动时探测、首次使用时探测，还是直接尝试并回退？
5. 是否需要真实视频预览？若需要，解码与渲染成本要单独立项。
6. 批量处理是否需要“单文件覆盖规则”？会影响 TaskSettings 数据模型。
7. 思源黑体是否随包分发？需要确认授权与体积，或继续使用系统字体回退。
8. 取消的语义：立即强杀，还是允许 FFmpeg 收尾并保留已完成文件？
