## 1. 引言
### 1.1 编写目的
本文档旨在明确“EasyAV”软件系统的功能、性能、界面及约束条件，为开发、测试和项目验收提供基准。本软件致力于解决 FFmpeg 命令行门槛过高的问题，面向“小白/懒人”用户，提供极低认知负荷的图形化交互体验。

### 1.2 预期读者
产品经理、C++ 开发工程师、UI/UX 设计师、测试工程师及最终用户代表。

## 2. 软件的一般性描述

### 2.1 软件产品与其环境之间的关系
*   **硬件环境**：具备基础图形处理能力的 PC（支持 OpenGL 3.3 及以上版本）。
*   **操作系统**：Windows 10/11 (后续可扩展至 macOS/Linux)。
*   **依赖环境**：软件自带或捆绑**经过定制裁剪**的静态编译的 FFmpeg 核心库/二进制程序。为兼顾“开箱即用”的用户体验与安装包体积控制，仅保留 H.264/H.265/AV1、AAC/MP3 等需求范围内必须的编解码器与滤镜模块。**用户无需自行配置环境变量**。
*   **交互关系**：用户通过界面拖拽文件 -> 软件后台生成标准化 FFmpeg 命令 -> 子进程/线程执行转码 -> 结果反馈到界面。

### 2.2 全局假设与约束
*   **核心假设**：用户不了解视频编码（H.264/H.265）、码率、帧率等专业概念。用户只知道“我想把视频变小”、“我想提取音乐”、“我想发朋友圈”。
*   **设计约束**：**界面绝对不出现命令行参数（如 `-crf`, `-c:v` 等）**。所有复杂的参数设置必须被封装在后台预设中。
*   **数据安全约束**：默认情况下，处理输出不覆盖原文件（自动重命名，如 `原文件名_压缩.mp4`），防止用户误操作导致数据丢失。

### 2.3 全局业务规则
*   **“一键式”规则**：任何核心任务（如转码、压缩、提取音频），用户操作步骤不得超过 3 步（选择文件 -> 选结果 -> 点开始）。
*   **智能容错规则**：当 FFmpeg 执行报错时，UI 不允许直接抛出英文报错代码，需转换为通俗易懂的中文提示（如“文件损坏”、“权限不足”）。

## 3. 软件功能需求描述

### 3.1 软件功能概述
本软件依托 FFmpeg 提供多媒体处理能力，必须包含以下核心功能边界：
1.  **格式转换**（容器转换）；
2.  **音视频转码**（H.264/H.265/AV1、AAC/MP3等）；
3.  **剪辑与拼接**（按时间裁剪、合并、提取/去除音轨）；
4.  **常用简单滤镜**（缩放、裁剪、旋转、图片/文字水印）；
5.  **封装与流处理**（分离/合并音视频流）；
6.  **截图与录屏**（抽帧、缩略图、桌面/摄像头录制）；
7.  **硬件加速**（NVIDIA NVENC/NVDEC、Intel QSV等）；
8.  **批量处理**（一键处理海量文件）。

### 3.3 软件需求的分析模型（极低认知负荷化设计）

针对上述功能，UI 层的“降维翻译”要求如下：

#### 3.3.1 基础文件与队列管理
*   **拖拽支持**：支持从 Windows 资源管理器直接拖入文件或文件夹。
*   **队列列表**：显示文件名、格式、时长、大小。支持移除、清空。

#### 3.3.2 场景化功能模块（核心）
*   **编码转换模块**（V0.2 起为首场景）：
    *   *UI 呈现*：三张目标卡片——H.264（最兼容，解决播放器打不开）、H.265（体积更小）、只要声音（MP3）；
        输出容器 MP4 / MKV；“顺便瘦身”开关控制是否显示质量滑块。
    *   *底层实现*：任意常见输入编码/容器（HEVC / AV1 / FLV / MKV…）解码后重编码为 H.264 或 H.265，
        自动映射 `-crf` / `-preset`；H.265 + MP4 写入 `hvc1` 标记；若勾选显卡加速，
        优先调用 `h264_nvenc` / `hevc_nvenc`，失败则静默回退 CPU。**V0.2 不提供 AV1 作为输出目标。**
*   **剪辑与拼接模块**：
    *   *UI 呈现*：可视化时间轴（可用简易双滑块表示起止时间）。支持多文件合并（需文件编码格式一致）。
    *   *底层实现*：无损裁剪（`-c copy`）或重编码裁剪；提取音频直接剥离视频流。
*   **滤镜与调整模块**：
    *   *UI 呈现*：提供“旋转90度”按钮、“画面裁剪”比例选项（1:1, 16:9, 9:16）。添加水印支持“上传图片”和“输入文字”，**支持在预览界面（如果实现了预览功能）直接拖拽水印位置**。
*   **录屏与截图模块**：
    *   *UI 呈现*：点击“录制屏幕”或“录制摄像头”大按钮，开始/停止。
    *   *底层实现*：调用 FFmpeg 的 `gdigrab`（Windows）或 `dshow`（摄像头）。截图模块支持“每隔X秒抽一帧”。
*   **批量处理模块**：
    *   *UI 呈现*：当队列中存在多个文件时，对第一个文件设置好“压缩/转码/加水印”规则后，一键应用至全队列。

#### 3.3.3 进度与交互反馈
*   提供全局进度条。解析 FFmpeg 的 `-progress pipe:1` 输出，实时计算 `已处理时长/总时长`。
*   提供“取消（中止）”按钮，安全结束 FFmpeg 子进程。

## 4. 其它软件需求描述

### 4.1 性能要求
*   **响应速度**：UI 渲染帧率在正常设备上保持 60 FPS（基于 Dear ImGui 和 GLFW 的高效渲染）。
*   **并发与解耦**：**严禁阻塞 UI 主线程**。文件处理（FFmpeg 调用）必须放在独立的后台线程（Worker Thread）或通过子进程异步执行。线程间通过线程安全的队列（如 `std::mutex` + `std::queue`）传递进度和日志数据。
*   **资源占用**：在空闲状态下，CPU 占用应接近于 0%，内存占用小于 100MB。

### 4.2 设计约束
*   **UI 框架**：必须使用 Dear ImGui + GLFW + OpenGL3。
*   **字体与渲染**：必须内嵌中文字体（推荐思源黑体），解决 ImGui 默认不支持中文的问题。
*   **命令注入防护**：在 C++ 拼装 FFmpeg 命令或调用 `CreateProcess`/`popen` 时，必须对文件路径进行严格转义处理（处理空格、中文、特殊字符），**严禁直接将用户输入拼接成裸 Shell 字符串**。

### 4.3 界面要求
*   **视觉风格**：遵循极简主义，使用大图标、大按钮、隐藏高级设置（折叠面板）。
*   **防呆设计**：当用户没有添加文件就点击“开始”时，对应按钮应为灰色禁用状态，或弹出友好的遮罩层提示。
*   **语言**：仅支持简体中文，文案需口语化（如使用“视频瘦身”代替“压缩转码”）。

### 4.4 进度要求（建议的迭代模型）
*   **V0.1 (MVP)**：完成 C++ 调用 FFmpeg 子进程的封装，实现拖拽添加文件、基础格式转换（MP4转MP3）、进度解析、取消任务。
*   **V0.5**：完善压缩/转码模块，加入硬件加速自动检测。完善 ImGui UI 布局和主题美化。
*   **V1.0**：加入剪辑、简单滤镜（水印）、录屏功能。实现批量处理逻辑。
*   **V1.5**：增强异常处理能力，错误代码全面汉化，实现完整的“小白可用”版本。

### 4.5 交付要求
*   源代码（C++）。
*   可执行文件（.exe）。**必须包含 FFmpeg 的动态链接库（.dll）或静态编译打包**，做到解压即用，绿色免安装。
*   《用户使用说明书》（图文并茂，仅说明功能操作，不涉及底层原理）。

### 4.6 验收要求
*   **场景验证**：找 3 名完全不懂视频技术的普通用户，在不提供任何指导的情况下，要求他们将一个 100MB 的 MP4 视频“变小”，并成功提取其中的背景音乐。
*   如果在 3 分钟内，用户全程未产生困惑（例如问“什么是码率”），且成功输出文件，则界面易用性验收通过。
*   后台异常退出率在连续处理 20 个主流视频文件时低于 5%。

---

### 补充：针对 C++ + ImGui 技术栈的额外开发建议
1.  **UI 主题化**：利用 ImGui 的 `ImGui::StyleColorsLight()` 或自定义 `ImGuiStyle`，调整 `WindowRounding`, `FrameRounding`, `FramePadding`，把默认的“开发者工具黑框框”变成圆润现代的界面。
2.  **中文显示**：使用 `io.Fonts->AddFontFromFileTTF("SourceHanSansCN-Regular.ttf", 18.0f, NULL, io.Fonts->GetGlyphRangesChineseFull());` 加载中文字体。
3.  **FFmpeg 执行**：建议使用 Windows API `CreateProcess` 隐藏控制台窗口（或指定 `CREATE_NO_WINDOW` 标志），否则每处理一个文件就会弹出一个黑框，极度影响小白体验。通过匿名管道（Pipe）捕获 FFmpeg 的 stderr 输出以解析进度和错误。
